# 08 · 重构蓝图（设计稿，不含代码）

> 本文只给**架构决策与边界**，不写实现代码。目标是：保留原工具「root 全量备份 + 极小依赖 + 多用户」的能力，同时消灭 `07` 里列出的正确性与安全缺陷。

---

## 1. 目标 / 非目标

### 目标
1. 与 v1 备份数据**只读兼容**（能识别并恢复老备份），写盘采用**新格式 v2**；
2. 恢复流程**可校验、可回滚、原子**；
3. 权限边界清晰：一个「高权执行层」，其余全是普通 App 代码；
4. 备份包**可被第三方工具校验**（清单自描述、sha256、版本化）；
5. 支撑多用户 / 多存储（内部、SD、OTG、rclone 挂载）；
6. 可观测：结构化进度与错误码，可中断、可续跑（至少能安全取消）。

### 非目标（第一期不做）
- 跨设备云同步 / 服务端；
- 增量与去重（可放在 v2.1，格式已预留）；
- 无 root 的降级方案（Shizuku/ADB）——可作为独立后续 ADR，但格式与执行层要能替换实现；
- 应用内浏览备份内容（解包浏览）。

---

## 2. 分层与模块

```
:app                    UI（Activity/Compose）、导航、ViewModel、权限引导
  │
:feature-app-backup     应用备份/恢复界面 + 状态机
:feature-settings       设置
:feature-logs           日志查看
  │
:domain                 纯 Kotlin：实体、用例、状态机、错误模型（无 Android 依赖）
  │
:data                   仓库实现：PackageRepository / BackupRepository / PrefsRepository
  │
:privileged             高权执行层抽象（唯一允许碰 root 的地方）
  ├─ RootShell          长生命周期 root shell（命令通道）
  ├─ RootIpc            自建 AIDL root 服务（包管理 / 文件 IO / 属性查询）
  └─ NativeTools        busybox / zstd / toolkit 的部署与版本管理
  │
:archive                归档格式 v2：Manifest 读写、tar/zstd 管道、校验、路径安全
  │
:core-ui / :core-common 主题、日志、协程工具、格式化
```

依赖规则：

- `:domain` 不知道 root 存在，只依赖接口（`PrivilegedExecutor`、`PackageQuery`、`FileGateway`）；
- `:privileged` 与 `:archive` 是**唯一**能出现在 `su` 命令里的字符串来源（集中审计、集中转义）；
- UI 层**禁止**拼接 shell 字符串。

## 3. 执行层设计（替代 libsu 的部分职责）

原实现把「root 服务 + root shell」都用 libsu 硬编码，重构建议**保留 libsu 作为实现之一**（成熟、坑已被踩过），但把它藏在接口后：

| 接口 | 职责 | 关键契约 |
|---|---|---|
| `PrivilegedShell` | 长驻 root shell，`run(Command) : CommandResult`；脚本引擎在启动时注入一次 | 命令必须**结构化**（argv + 可选管道），禁止裸字符串拼接；执行前统一转义 |
| `PrivilegedIpc` | root 进程内的 AIDL：取包列表（跨用户）、改 enabled 状态、取启动 Intent、`exists/list/read/write/delete/stat/getSelinuxContext` | 所有路径参数做规范化+白名单根目录校验（见 §6） |
| `NativeToolRepo` | 解压/校验/更新 `busybox`、`zstd`、`toolkit`，带 sha256 与 ABI 选择 | 版本号写入 prefs 键 `tooling_version`，与备份清单里的 `toolVersion` 对应 |
| `CapabilityProbe` | 启动自检：root 可用？`--mount-master` 可用？`restorecon` 可用？`pm install` 语义（34+/35）？ | 产出 `EnvironmentReport`，UI 直接展示可用的功能子集 |

**Shell 脚本是否保留？** 建议**保留但工程化**：

- 优点：tar/zstd/管道/`pm install-create` 这类操作在 shell 里最自然，且能复用 busybox；
- 改造要求：
  1. 脚本拆成 `lib/*.sh` 多个文件（`env.sh`、`archive.sh`、`apk.sh`、`restore.sh`、`selinux.sh`），由加载器按顺序注入；
  2. 每个函数只接受**位置参数**，内部对变量一律加引号，不再用 `eval`；
  3. 所有「可失败步骤」显式 `|| return N`，并输出**结构化事件行**（如 `EVT|stage=tar|part=apk|bytes=123|rc=0`）供 UI 解析进度；
  4. 不使用别名（`alias tar=...`），改为显式函数（消除「必须同一 shell 会话」的隐性依赖）；
  5. 全部函数可被一个 **host 侧 harness** 单测（见 §8）。

## 4. 备份格式 v2

### 4.1 目录布局（每应用一份清单，兼容多份备份）

```
<backup_home>/
├── .nomedia
├── toolkit.json                        # 备份根元数据（格式版本 / 写入者 / backupHomeId）
├── apps/
│   └── <pkg>/
│       ├── index.json                  # 备份列表的派生缓存（可重建，非真值）
│       ├── icon.png
│       └── <backupId>/                 # <epochMillis>-<8 hex>，防同毫秒覆盖
│           ├── manifest.json           # 单次备份的完整清单（唯一真值）
│           ├── package.tar.zst
│           ├── apk_obb.tar.zst
│           ├── internal_data.tar.zst
│           ├── internal_device_protected.tar.zst
│           └── external_data.tar.zst
├── self/
│   └── BackupToolkit-<versionCode>.apk  # 当前版本自身备份（只保留当前版本）
└── .toolkit/                           # 锁 / 取消标志 / 恢复 journal（非备份数据）
```

> 字段级定义、v1 适配与迁移见 `09-格式v2规范.md`；本节只保留蓝图级摘要。

### 4.2 单次备份清单（关键字段）

> 完整字段表、类型、必填性与示例见 `09` §3.2；`parts[]`/`kind` 枚举见 `09` §3.2.7。

| 字段 | 说明 |
|---|---|
| `schema` | `2`，格式版本 |
| `backupId` | `<epochMillis>-<8 hex>`；唯一、可排序、防同毫秒覆盖 |
| `status` | `in_progress` / `complete` / `partial` / `failed`；恢复只接受 `complete`/`partial`，`in_progress`/`failed` 拒绝（除非显式强制） |
| `createdAt` / `finishedAt` | UTC RFC 3339；`in_progress` 时 `finishedAt=null` |
| `tool` | `{name, version, versionCode}` |
| `device` | `{sdk, abi, manufacturer, model, buildFingerprint}`（仅诊断） |
| `package` | `{name, label, versionName, versionCode, userId, userSerial, appId, uid, signerSha256, isSystem}`；**备份时快照**，恢复不再猜 uid |
| `selinux` | `{dataType, dataContext, externalDataType}`；`dataType` 是跨用户可移植的类型级上下文 |
| `requestedModes` | v1 兼容的三档：`apk`/`user`/`data`（仅 UI/展示） |
| `requestedKinds` | 展开后的 kind；恢复以它为准 |
| `skippedKinds` | `{kind, reason}`；`absent` 是正常情况，不是失败 |
| `errors` | `{kind, code, message, at}`；解释 `partial`/`failed` |
| `parts[]` | `{kind, file, compression, level, sizeBytes, sha256, entryCount, uncompressedBytes, excludes}`；`sourcePath` 不写（deprecated）；另有 `seq`/`plaintextSha256`，见 `09` §3.2.7 |
| `totals` | `{sizeBytes, uncompressedBytes, partCount}`；派生缓存 |
| `note` | 用户备注 |
| `encryption` | 加密元数据；未加密为 `null`。M4/v2.1：`alg/kdf/nonce/tag/chunkSize`；`sha256` 对密文、`plaintextSha256` 对明文 |
| `origin` | `{format:"v2"}`；迁移来的 v2 清单可带 `{format:"v1", …}` |

`kind ∈ {package, apk_obb, internal_data, internal_device_protected, external_data}`，预留
`external_media`/`external_files`（未定义前按 `unsupported` 处理）。**用语义名替代原 `apk/user/data`**；v1 映射：
`apk→package`、`apk_obb→apk_obb`、`user→internal_data`、`user_de→internal_device_protected`、`data→external_data`、
`obb→apk_obb`（v1.1.0 前）。

`uid` 用算术：`uid = userId × 100000 + appId`；不要照抄 v1 的 `USER_ID$appid` 字符串拼接
（`appId < 10000` 且 `userId > 0` 时会错，见 `09` §5.5）。

### 4.3 兼容策略

- **读**：v1 的 `AppBackup/<pkg>/!BackupInfo!<pkg>.json` + `<ts>-<part>.tar.*`（以及 v1.1.0 前的扁平布局）由
  `LegacyV1Adapter` 转成内存中的 `BackupSet`，恢复走同一流水线；字段/分卷映射见 `09` §5。
- **写**：只写 v2；迁移分两层：`reindex`（只建索引，不写 v1）与 `migrate`（复制成 v2 目录并重新哈希）。
- `migrate` 必须**幂等**（`sourceKey` + 确定性 `backupId`）、可中断、复制后重新计算 sha256；v1 原文件保留，
  删除是单独的显式动作。不能只写一份清单就信任 v1 分卷（外部可能已改）。
- 恢复 v1 时仍必须执行归档安全校验（`10` §7）；v1 没有哈希只影响完整性告警，不影响安全校验。

## 5. 恢复流水线（状态机）

> 完整状态定义、迁移表、失败矩阵、回滚协议、取消点与 journal 见 `10-恢复状态机与错误码.md` §2–§7。
> 这里只保留蓝图级摘要。

```
Preflight   → 校验清单完整性（sha256/大小）→ 校验设备条件（空间、目标包是否存在、签名是否一致）
Prepare     → 解析目标 uid（清单 `appId` + IPC 校验）/ SELinux 期望值（清单 `dataType`）；创建 staging 目录（与目标同分区，保证 rename 原子）；am force-stop 后 pidof/ps 复核
Extract     → 解包到 staging（条目白名单校验）；逐 part 回报进度
Install     → APK：pm install-create/write/commit（或兼容模式 stdin）；失败 → 数据未动，APK 可能已更新
Commit      → 目标目录 rename 为 <父目录>/.toolkit-bak-<restoreId>-<kind>；staging rename 为 <path>；lib 软链（仅 internal_data）；chown -hR uid；restorecon -RF
Verify      → 抽查关键文件属主/上下文；必要时跑「应用能否被拉起」的软校验
Cleanup     → 删除 .bak/staging；删除失败只告警并保留残留（不回滚已验证的成功）
```

补充约束（与 `10` 对齐）：

- staging 必须是目标的**兄弟目录**（同文件系统）；`mv` 返回 `EXDEV` → `E_STAGING_NOT_SAME_FS`，不得退化为 `cp -r`。
- 提交顺序：`apk_obb` → `external_data` → `internal_device_protected` → `internal_data`；任一失败按已提交项逆序回滚。
- `Cleanup` 删除 `.bak` 失败**不回滚**：新增 `W_CLEANUP_INCOMPLETE`，恢复已成功，残留路径交给用户清理。
- APK 安装没有事务回滚；`Install` 成功而后续失败时 `dataState=installed_data_old`，UI 明确提示「应用已更新、数据未恢复」。
- `am force-stop` 后用 `pidof`/`ps` 复核 `<pkg>` 与 `<pkg>:*`；仍有进程 → `E_APP_NOT_STOPPED`（rc=47）；
  `allowRunningApp=true` 才继续并报 `W_APP_LEFT_RUNNING`；无进程但 `am` 返回非 0 仅记日志。
- uid remap：同包名 + 同签名；本次新装自动 `W_UID_REMAPPED`；已安装且 appId 不同默认 `E_UID_MISMATCH`，
  `allowUidRemap=true` 才继续并 `W_UID_REMAPPED`；签名不一致始终 `E_SIGNER_MISMATCH`；v1 无 `appId` 不触发。
- 取消只在 Commit 前生效；`Install commit` 之后取消被延迟（`W_CANCEL_DEFERRED`）。

要点（全部针对 `07` 的缺陷）：

| 原缺陷 | v2 对策 |
|---|---|
| uid/SELinux 靠猜 | uid 以清单 `appId` 为准；SELinux 用清单 `dataType` 校验 `restorecon -RF` 的结果（递归；v1 的 `-F` 只是非递归观测）；只有 v1 的 uid 才回退探测并**告知用户**，SELinux 不猜父目录，未知时告警或失败（`10` §5.4） |
| `mv` 失败静默 | 每一步检查返回码；Commit 前失败只清理 staging，Commit 中失败进入 `Rollback` |
| 半截解包 | 解到 staging，目标目录在 `Commit` 前完全不动 |
| 路径逃逸 | 按 tar 头解析条目：拒绝绝对路径、`..`、控制字符、设备/管道、越界符号链接；解包前后各校验一次 |
| 无完整性 | 每个 part 的 sha256 + 总大小，解包前后各校验 |
| 无空间预检 | 预检 `Σ uncompressed（缺失则 size×3） + 现有目标大小 + 64 MiB` vs 可用空间 |
| 应用还在跑 | `am force-stop`；关键应用（有 SQLite WAL）可选 `sqlite3 .backup` 快照法 |
| 备份期间应用被 STOP 卡死 | 全程 `trap 'resume_app' EXIT INT TERM` |

## 6. 安全设计

1. **路径白名单**：所有特权文件操作限定在 `backupRoot`、`/data/user*/<uid>/<pkg>`、`/data/user_de*/<uid>/<pkg>`、`/data/media/<user>/Android/{data,obb,media}/<pkg>`、`/sdcard/Android/{data,obb,media}/<pkg>`、`/data/local/tmp/toolkit-<uuid>`，以及同父目录的 `.toolkit-staging-*`/`.toolkit-bak-*`；`canonicalize` 后必须落在根内（拒绝符号链接逃逸）。
2. **归档条目校验**（关键）：按 tar 头解析条目（不依赖 `tar -tv` 文本），任何越界条目 → 拒绝整包并报 `E_ARCHIVE_UNSAFE`。
3. **恢复确认**：显示清单摘要（应用名、版本、大小、时间、parts），用户显式确认后才 `commit`。
4. **不修改全局系统设置**：安装校验相关的 `settings put` 一律不做；如需（例如某些 ROM 装不上低 targetSdk），改为「临时、恢复原值、仅当前会话」并明确告知。
5. **不伪造安装来源**：去掉 `-i com.android.vending`（如需保留，做成显式「兼容模式」选项并说明后果）。
6. **可选加密**：`aes-256-gcm` + 密钥来自 Android Keystore 或用户口令（Argon2 派生）；密钥丢失 = 备份不可恢复，须在 UI 强提示。
7. **签名校验分两类**：应用自身的「防重打包门禁」失败只告警、不阻断（用户有权修改自己设备上的软件）；但恢复流水线里的「备份 APK/清单 `signerSha256` vs 目标包」不一致仍是 **fatal**（`E_SIGNER_MISMATCH`），避免把别的应用的 APK/数据装到目标上。
8. **命令注入**：所有 shell 参数经 `shQuote()`；备份目录/备注等用户输入永不进入未加引号的上下文。
9. **停止与 uid remap**：force-stop 后有进程默认中止 `E_APP_NOT_STOPPED`（`allowRunningApp=true` 才继续）；
   uid 重映射只在同包名+同签名下允许，新装自动 remap、已安装需 `allowUidRemap`，签名不一致始终 fatal。

## 7. 并发 / 调度 / 可观测性

| 主题 | 设计 |
|---|---|
| 任务执行 | 单线程串行队列（同一时刻只允许一个备份/恢复任务，避免 zstd 抢 CPU + 保证 IO 顺序） |
| 生命周期 | 前台服务 + 通知（进度、取消按钮）；进程被杀不影响，因为作业在 root shell 里；重启后用「任务日志」标记未完成任务为 `interrupted` |
| 取消 | 取消协议：`<home>/.toolkit/cancel/<taskId>` 标志文件（或 journal 的 `cancelRequested`），Extract 每个 part/每 N 个条目检查；`Install commit` 之后不中断；不做 `kill -9`（会留半截文件） |
| 进度 | 两层：任务级（第 i/N 个应用）+ part 级（字节数，tar 侧用 `-v` 或 `zstd --progress` 估算，或先 `stat` 出总大小加权） |
| 日志 | 结构化事件行（`EVT\|...`）+ 人类可读日志；**稳定错误码**（`E_UID_UNKNOWN`、`E_ARCHIVE_UNSAFE`、`E_SPACE`、`E_INSTALL_COMMIT`…）+ `dataState`。完整表见 `10` §8 |
| 诊断包 | 「导出诊断」= 环境自检报告 + 最近任务事件 + 版本信息（脱敏，不含用户数据） |

| 层 | 做法 |
|---|---|

| 格式兼容 | 构造 v1/v2 fixture 目录，断言 `LegacyV1Adapter` 解析结果与 v2 清单等价 |
| 恢复安全 | 构造恶意 tar（`../`、绝对路径、symlink 逃逸、设备文件），断言被拒绝 |
| 状态机 | 用例覆盖每个 stage 的失败注入（返回码、超时、空间不足、IPC 断开），断言目标目录最终状态 |
| 设备矩阵 | Android 8/10/12/14/15 × root 方案（Magisk/KernelSU/APatch）× 多用户/工作资料；至少验证「备份→卸载→恢复→应用能启动」闭环 |

## 9. 里程碑

| 里程碑 | 交付 | 验收 |
|---|---|---|
| M0 | 环境自检 + 特权层骨架（root shell / IPC 抽象、工具部署）+ 格式 v2 定义（`09`）+ 恢复状态机/错误码（`10`） | 能列出应用、能跑 `id` 与 `tar --version` |
| M1 | 备份：`package` + `internal_data` + `external_data`，清单 + sha256 + 进度 | 与 v1 备份体积/内容等价；中断后可识别半截包 |
| M2 | 恢复：staging + 原子换名 + 回滚 + 归档条目校验 + 清单驱动 uid/上下文 | 恢复后应用能启动；恶意包被拒 |
| M3 | v1 迁移与只读兼容；多用户/多存储（SD/OTG/rclone） | 老备份可恢复；0 号用户以外正常 |
| M4 | 进度/取消/前台服务/诊断导出；加密（可选） | 长任务可取消且无残留；加密包可恢复 |

## 10. 明确「不要照抄」的清单

1. 用 `eval` 拼接 tar 参数 → 改 argv 数组；
2. `alias` 依赖同一 shell 会话 → 改显式函数/绝对路径；
3. uid / SELinux 靠猜 → 写进清单；
4. `mv` 失败静默、无 `trap` → 状态机 + 失败即回滚；
5. 明文备份 + 无校验 → 校验（必做）+ 加密（可选）；
6. `settings put global` 改系统全局 → 不做或可逆且显式；
7. `pm install -i com.android.vending` 伪造来源 → 去掉或显式化；
8. 用文件名正则当唯一真值 → 清单为真值，文件名仅提示；

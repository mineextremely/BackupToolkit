# 05 · 功能清单与 UI 流程

全部功能按「字符串资源 + 实际调用链」双向核对过。✅ = 有真实实现；⚠️ = 有 UI 无实现（死代码）；❌ = 完全没有。

## 2. 关键界面流程

### 2.1 主界面（MainActivity）

```
AppBar: 搜索 | 排序 | 菜单（重新加载 / 新建应用备份 / 管理应用备份 / 运行 / 设置 / 关于 / 错误日志 / 更新备份目录结构）
列表头 app_list_header：
    ├─ tv_user_id  「用户0」   ← 长按可改系统用户名
    └─ storage_list  RadioGroup ← 每块存储一个单选项，文本=挂载路径；长按选目录（FileSelectActivity）
列表 item_app：图标(点击=反选整行) | 应用名+包名 | 版本 | 状态徽标(旧版本/未安装/系统应用) | 备份时间
```

细节：
- 存储列表来自 root 服务解析 `/proc/self/mounts`，`fuse.rclone` 类型额外保留（并给路径加 `:` 前缀以区分内部路径）。
- 「不允许选根目录」：`m1144implements(path) < 2` 时提示 `not_recommend_using_root_directory`。
- 首次列表加载完会通过 root shell 关掉 Play 校验：`settings put global verifier_verify_adb_installs 0`、`settings put global package_verifier_enable 0`、`settings put secure install_non_market_apps 1`（为了让 `pm install` 恢复 APK 顺利）。

### 2.2 批量备份/恢复（AppBackupRestoreActivity）

```
表头：mode_all 复选框 + 「已选择: apk:N user:M data:K」+ 计数「N个应用 / N个应用有备份」
列表 item_app_options：每行 = 图标 | 名称 | apk 复选框 | user 复选框 | data 复选框 | 备注
底部按钮：备份/恢复 | 移除/删除
菜单：切换到(新建/管理) | 搜索 | 排序 | 完成后取消选项 | 帮助
```

- 备份模式下三个复选框 = 「这次备份哪些档位」；
- 恢复模式下三个复选框 = 「这次恢复哪些档位」，不存在的档位（分卷缺失）置灰不可选；
- 「已选择」计数由 `p029super.Cdefault.f1863abstract` 这个 `Map<part, Integer>` 实时统计。

### 2.3 应用信息页（AppInfoActivity）

```
头部：图标 | 应用名 | 包名 | 版本 | UID | 安装/更新时间
列表 item_backup：每条备份 = 时间 | 版本 | 大小提示 | 备注
底部操作栏 bt_bar
菜单：启动应用 | 冻结/解冻 | 清空数据 | 强行停止 | 卸载应用 | 系统设置 | 备份 | 删除备份 | 搜索备注
```

非 0 用户时：先尝试 `pm grant <self> INTERACT_ACROSS_USERS`，再校验 `checkSelfPermission`；跨用户 Intent 用 `startActivityAsUser`。

### 2.4 目录选择器（FileSelectActivity）

- 复用 libsu `FileSystemService` 浏览任意目录（root 视角）；
- 支持手输路径 + 右上角「重新加载」；
- 用 `select_folder` / `select_file` 区分模式，结果以 `sd_id`/`path`/`root_path`/`select_path` 回传。

### 2.5 设置页（`res/xml/pref_setting.xml`，原生 PreferenceFragment）

```
备份：  备份格式(List) | 压缩等级(Edit) | 备份自身(Check) | 自定义备份目录(Check) | 备份应用图标(Check)
恢复：  兼容模式(Check)
显示：  显示时间(Check)
```

## 3. 「三档语义」的用户可见解释（`backup_restore_description` 原文）

```
apk:  应用安装包，支持分包应用(Split APK)
user: 位于 /data/user/ 下的数据
data: 位于 共享存储/Android/data/ 下的数据
```

> 重构时**建议改名**：`user` → `internal-data`，`data` → `external-data`，`apk` → `package`（可保留旧名做兼容映射）。

## 4. 未实装 / 可疑代码的位置（便于重构时决策是否补齐）

| 位置 | 现象 |
|---|---|
| `FileBackupRestoreActivity` | `onClick` 只处理 `R.id.cb`；确定/删除按钮无 handler；无任何 `app_backup_file` 之类的 shell 调用；`file_backup_list` 偏好无人写入 |
| `MainActivity.onOptionsItemSelected` | 出现 `R.string.backup_file` 分支，但 `onCreateOptionsMenu` 里**从未 add** 该项 |
| `Service.Cthrow.m120finally` | 一个 90 行的「fastjson writer 工厂」方法被塞进了 shell 工具类，属于反混淆后的错位代码（很可能是 fastjson2 内部类被合并），不影响功能 |
| `p004class.Cnative.b/mo473break/c` | `SDK_INT > 32 ? getPackageInfo(...) : getPackageInfo(...)` 两分支完全相同 |
| `p003catch.Cwhile.m460default` | 日志轮转用了 `compareTo` 而非 `renameTo`/`delete`（见 `07`） |
| `run_shrc.sh` 注释掉的 `is_ok/not_ok` | 死函数 |

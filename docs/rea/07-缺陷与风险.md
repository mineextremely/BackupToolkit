# 07 · 缺陷、风险与「坑」清单

> 目的：重构时**不要照抄**这些问题；有些是功能缺失，有些是会把用户数据搞坏的正确性缺陷，有些是安全风险。

## 1. 功能死代码 / 半成品

| 位置 | 问题 | 影响 |
|---|---|---|
| `ui.File.FileBackupRestoreActivity` | 只画列表 + 复选框；`onClick` 仅处理 `R.id.cb`；「备份/恢复/删除/移除」按钮**没有任何 handler**；全工程没有任何 `file_backup` 相关的 shell 调用 | 「备份文件」功能是**空壳**，点了什么也不会发生 |
| `MainActivity.onOptionsItemSelected` | 有 `R.string.backup_file` 分支，但 `onCreateOptionsMenu` 从未 `add` 这一项 | 入口彻底不可达 |
| `pref` `file_backup_list` | 默认 `"DCIM:Download:Pictures"`，但没有任何写入方 | 只是 UI 文案 |
| `root_shrc.sh` | `is_ok()` / `not_ok()` 被注释掉 | 无害死代码 |
| `c.Cimport.m439abstract` | 反编译后出现大段重复分支、`iM435extends` 未初始化即可用（jadx 报 "code duplicated / instruction removed"） | 原始代码高度内联+复制粘贴，**可读性极差**；重构时应重新抽象为「收集 → 执行 → 落盘」三段式 |

## 2. 正确性缺陷（会导致恢复失败或数据损坏）

### 2.1 uid 靠「猜」

恢复时必须把目录属主改回目标应用 uid（否则应用读不到自己数据）。当前实现是三级回退：

```sh
app_uid=$(STI "$app_user_path" u)                              # 目录还在？用它的属主
   || app_uid=$USER_ID$(cat /config/sdcardfs/$_APP_PKG/appid)  # sdcardfs 映射
   || app_uid=$USER_ID$(grep -o "^$pkg [0-9]*" /data/system/packages.list | ...)
```

风险：

- 三级回退分别在「目录已被删除（全新恢复）」「无 sdcardfs（Android 11+ FUSE 设备）」「packages.list 格式变化」时失效；
- **一次全都不中，就报「应用uid获取失败」直接不恢复**；
- 若猜到的 uid 与真实 uid 不同（多用户/工作资料/克隆应用），`chown` 会把数据挂到错误的 uid 上，应用表现是「数据丢了」。

> 重构建议：**备份时就把 `uid / packageName / SELinux 上下文 / apk 路径` 写进清单**，恢复时以清单为准，仅在缺失时才回退推断。

### 2.2 SELinux 上下文靠父目录猜

```sh
restorecon -F "$1"
ctx=$(LZ -d "$1" | awk '{print $1}')            # 父目录的 -Z 首列
[ -n "$ctx" ] && chcon -R "${ctx%:c*}" "$1"     # 去掉 :c<类别> 后缀后整树刷
```

- 若父目录本身标签异常（例如 `_old` 残留、或 sdcardfs→FUSE 迁移后父目录为 `unlabeled`），会**把错误标签刷满整棵数据目录**；
- `restore user_de 1` 才会 `recon`，`restore data`（共享存储）不刷 —— 但共享存储通常无需；
- `ls -Z` 输出格式在部分 ROM / busybox `ls` 下可能不同，`awk` 取列会错。

### 2.3 回滚不完整

```sh
mv "$path" "${path}_old" 2>/dev/null                     # 忽略失败！
if decompress ...; then rm -rf "${path}_old"; ...        # 成功才删备份
else rm -rf "$path"; mv "${path}_old" "$path"; fi        # 失败回滚
```

- `mv` 失败被静默忽略 → 后面 `decompress` 直接覆盖原数据，**旧数据已丢但脚本不知道**；
- `rm -rf "$path"` 在 `decompress` 部分成功后执行，若中途 `rm` 失败/被杀，留下半残目录；
- 若解包成功但 `chown` 失败（`set -e` 未开启），脚本仍会 `echo '完成'`。

### 2.4 备份一致性无保障

```sh
killall -s STOP "$_APP_PKG" 2>/dev/null   # 失败也继续
eval "$3"
killall -s CONT "$_APP_PKG" 2>/dev/null
```

- `killall` 失败（部分 ROM 无该 applet/权限、或进程名与包名不一致，如 `:remote` 子进程）时**仍然继续备份**，可能拿到不一致的数据库快照；
- 脚本**没有 `trap`**：中途 `kill`/超时/断电 → 应用停在 `T_STOPPED`，用户看到「应用无响应」；
- 备份的是活跃数据库文件，没有 `sqlite3 .backup` / WAL checkpoint，恢复后个别应用（如微信）可能要求重新登录或报数据库损坏。

### 2.5 压缩与空间

- `zstd --priority=rt` + `-T0`：备份期间抢占实时优先级，低端机上会明显卡顿；
- **没有任何可用空间预检**，磁盘写满时 tar/zstd 报错，但已产生的半截分卷**不会被清理**（只在下一次同名备份前 `rm -f "$CP_prefix<part>.tar"*`）；
- `zstd -19`（`--ultra`）在手机上可能比备份本身还慢，UI 无进度、无百分比，只有 `echo_n '备份apk:'` 这种粒度。

### 2.6 日志轮转写错

```java
if (file.length() / 1024 > 1024) {          // >1MB
    ...
    File old = new File(f660default.getPath() + ".old");
    old.delete();
    f660default.compareTo(file2);           // ← 应该是 renameTo，写成了 compareTo
}
```

`compareTo` 是纯比较、无副作用 ⇒ **error.log 永远不会被切走**，只会无限增长（直到写满分区）。`LogsActivity` 里读 `.old` 的逻辑因此永远读不到东西。

### 2.7 其它小问题

| 位置 | 问题 |
|---|---|
| `Service.Cthrow.m124volatile` | `getprop` 输出解析里对空行/末尾空串的处理很绕，`abilist` 为空时直接报「不支持CPU架构: 」（提示语里架构名为空） |
| `p004class.Cnative` | `SDK_INT > 32 ? getPackageInfo(...) : getPackageInfo(...)` 两个分支完全相同（复制粘贴残留） |
| `p004class.Cnative.mo481static` | 用 `" " + mountPoint` 子串去重，路径互为前缀时会误判 |
| `Service.Cthrow.m120finally` | 一个 fastjson2 writer 工厂被塞进 shell 工具类（反混淆错位），91 行死代码 |
| `p003catch.Cwhile.m460default` | 每次写日志都重开/复用 `PrintStream`，`checkError()` 失败时递归调用自身（尾递归，理论上可深） |
| `c.Cextends.mo410package` | 单方法 200+ 行、大量重复分支；`f621strictfp--`（排序失效标记）散落各处，容易漏 |
| `FileSelectActivity` 回传 | 路径校验依赖 `startsWith(root_path)` 字符串前缀，`/sdcard/foo` 与 `/sdcard/foobar` 会误通过 |

## 3. 安全风险

### 3.1 备份产物是明文

- 备份的是**应用私有数据**（含登录态、token、聊天数据库、SharedPreferences 中的密钥），却以 `tar.zst` 明文落在 `/sdcard/...`；
- 任何持有 `READ_EXTERNAL_STORAGE`/`MANAGE_EXTERNAL_STORAGE` 的应用、以及 USB 拷贝、云同步、`adb pull` 都能直接读走；
- 没有密码、没有加密、没有完整性签名。

### 3.2 恢复端是「以 root 解包外部可控文件」

- 分卷放在**其他应用可写**的 `/sdcard`；
- `decompress` 直接 `tar -xC <目标父目录>`，**未校验归档内的路径**（`../` 逃逸、绝对路径、符号链接）；
- 结合 root 身份 ⇒ 被篡改的备份包 = **以 root 向任意路径写文件**（典型提权链：改一个分卷 → 诱导用户点「恢复」）。
- 同理 `apk` 分卷被替换 → `pm install` 安装任意 APK。

> 这是重构时**必须修**的一条：解包前校验条目（拒绝绝对路径、`..`、设备文件、越界符号链接），或解到 tmp 后按白名单搬运。

### 3.3 命令拼接

- `app_init %s %s %s %s` 里 **备份目录未加引号**（`String.format("app_init %s %s %s %s", uid, backupHome, ...)`）；
- 备份目录可由用户在「自定义备份目录」里手输（`MainActivity` 弹 EditText、`FileSelectActivity` 手输路径）；
- ⇒ 目录名含空格/单引号/`;` 时会破坏命令；含 `'; rm -rf ...` 之类可构成**注入**（需要用户自己输入，风险有限，但重构时必须参数化）。

### 3.4 关闭系统安装校验

首次加载列表后会执行：

```sh
settings put global verifier_verify_adb_installs 0
settings put global package_verifier_enable 0
settings put secure install_non_market_apps 1
```

- 这是**全局、持久**的系统设置修改，会影响整机后续所有安装行为，且**卸载 App 后不会还原**；
- 加上 `pm install -i com.android.vending` 伪造安装来源（伪装成 Play 安装）。

### 3.5 自我提权尝试

非 0 用户时执行 `pm grant <self> android.permission.INTERACT_ACROSS_USERS`（该权限为 `signature|privileged`，常规 ROM 会失败）。设计上依赖 root 侧 `IPackageManager` 兜底，因此这条属于「无效但无害」的尝试；但它说明作者在按「能拿到就拿到」的思路堆权限。

## 4. 兼容性与可维护性风险

| 风险 | 说明 |
|---|---|
| 依赖 `--mount-master` | Magisk/KernelSU 的新版本对 mount namespace 处理有差异；失败会退化到普通 `su`，此时读不到其他挂载点 |
| 依赖 `/config/sdcardfs/<pkg>/appid` | Android 11+ 多数设备已是 FUSE，该路径不存在（回退到 packages.list） |
| 依赖 `/data/local/tmp` 可执行 | 部分 ROM 对 `/data/local/tmp` 加了 `noexec`（则 `*/bin/*` 与 `toolkit` 也受影响，因为它们在 app 私有目录，一般 OK） |
| `busybox` 仅 7 个 applet | 任何新功能想用 `stat`/`cp`/`sed` 都得再加 applet，或继续用 `toolkit` 补 |
| `restorecon`/`chcon` 语义 | Android 12+ 对 `chcon` 的限制、`/system/bin/chcon` 是否存在 |
| `pm install --bypass-low-target-sdk-block` | 仅 34+ 存在；34→35 语义可能再变 |
| libsu 5.x 单例限制 | 同进程只允许一个 root shell；`RunCmdActivity` 因此只能用**非 root** shell（与「运行 root 命令」的直觉不符，属设计妥协） |
| 无版本化清单 | 备份格式只靠文件名约定，未来加字段/改 part 名会破兼容 |

## 5. 重构优先级建议（按「修了收益最大」排序）

1. **恢复路径安全**：归档条目校验（防 root 任意写）+ 清单校验（sha256/大小/分卷完整性）；
2. **元数据自证**：备份时写入 uid / 包名 / SELinux 上下文 / 工具版本 / 压缩算法 / 分卷哈希，恢复时以清单为准；
3. **一致性**：备份前 `am force-stop` 或 `stop`+`sqlite3 .backup`、`trap` 保证 `CONT`、失败清理半截分卷、空间预检；
4. **原子性**：改为「解到临时目录 → 校验 → 原子换名（rename）→ 失败回滚」；
5. **可观测性**：进度事件（每条 tar 的字节数/当前 part）、错误码结构化；
6. **加密**（可选）：备份包用设备派生密钥或用户密码加密（zstd 本身不支持，需外层 AES-GCM 或 `age`）；
7. **清理遗留**：删掉文件备份死代码、把 `settings put global` 这类全局副作用改成「按需、可回滚、显式确认」。

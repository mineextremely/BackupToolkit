# 04 · 数据格式与元数据

全局 fastjson2 配置（`p003catch.Cthrow` 静态块）：

```java
Cswitch.f1188default |= JSONWriter.Feature.NotWriteDefaultValue
                      |  JSONWriter.Feature.IgnoreNonFieldGetter;
```

⇒ **默认值（0 / null / false）不写入 JSON**，因此「新备份」条目里常常只有 `backupTime` + 版本信息，其余字段缺省。重构解析时必须容忍字段缺失。

## 1. `!BackupInfo!<pkg>.json` —— 每个应用的备份清单

路径：`<backup_home>/AppBackup/<pkg>/!BackupInfo!<pkg>.json`

模型（`c.Cwhile` / `c.Cthrow`）：

```jsonc
{
  "pkg": "com.example.app",              // c.Cwhile.pkg
  "backupList": [                        // c.Cwhile.backupList : List<BackupEntry>
    {
      "name": "微信",                     // c.Cthrow.name      应用名快照（也用于列表显示）
      "versionName": "8.0.40",           // 备份时的 versionName
      "versionCode": 2400,               // 备份时的 versionCode
      "backupTime": 1730000000000,       // 备份时间（= 分卷文件名前缀 = CPId）
      "backupTime2": 1730003600000,      // 二次时间戳（备注/覆盖时刷新，见下）
      "note": "登录前状态"                // 用户备注，可空
    }
  ]
}
```

字段语义补充：

| 字段 | 语义 |
|---|---|
| `backupTime` | **主键**。既决定分卷前缀 `<backupTime>-*.tar.*`，也用于「按时间排序」「选中某个备份」 |
| `backupTime2` | 仅用于「最近一次备份/覆盖」排序（`m455volatile` 里 `j = backupTime2 != 0 ? backupTime2 : backupTime`），使「覆盖备份」后条目能冒泡到最前 |
| `name` | 备份时刻的应用名快照；应用卸载后仍能显示中文名 |
| `note` | 备注。搜索框会一并匹配（`搜索应用名、包名、备注`） |
| `versionCode` / `versionName` | 用于 `new/old version` 标记与「版本不同则置顶」排序 |

写盘时机（`c.Creturn.m446implements()`）：

1. 条目数 = 0 → 删除 `!BackupInfo!<pkg>.json`、`!icon!<pkg>`、并删除整个 `<pkg>/` 目录（**最后一个备份被删时自动清理目录**）；
2. 否则序列化整体覆写。
3. 图标：`backup_app_icon=true` 且（图标文件不存在 或 应用已升级）时，`Drawable → Bitmap → PNG` 写入 `!icon!<pkg>`；`backup_app_icon=false` 时完全不写。

删除单个备份（`m454transient(backupTime)`）：

```
listIterator 里找到同 backupTime 的条目 → remove
若剩 0 条：清空 f641if、Boolean[]，再 m446implements() → 触发目录清理
若删的是当前选中项：重新 m451protected(最后一个) 选中最新
```

## 2. `config.json` —— 备份根目录的「写入者版本」

路径：`<backup_home>/config.json`

```jsonc
{ "versionName": "1.1.1", "versionCode": 1113 }
```

模型：`c.Cfinally`。

用途（三条）：

1. **判断备份根目录是否为本工具产生**：不存在则认为是「别人的/旧的」目录，走 legacy 迁移流程（`IBackupManager.updateBackupDirStructure`）；
2. **判断「备份自身」是否需要刷新**：版本不一致 → 覆盖 `!app!.apk` 并重写 `config.json`；
3. 触发「更新备份目录结构」提示。

## 3. 分卷命名规范

```
<CPId>-<part><ext>
CPId  = System.currentTimeMillis() 十进制
part  = apk | apk_obb | user | user_de | data
ext   = .tar | .tar.zst | .tar.gz | .tar.xz | .tar.lz4   （由设置项 backup_ext 决定）
```

匹配用的正则（`p003catch.Cthrow.f659finally`）：

```
([0-9]+-)[a-z]+(?:_[a-z]+|)\.tar(?:\.[a-z]+|)
```

> 注意：正则不允许 `--` 之后的未知 part。若将来扩展 part 名，需要同步改正则，否则 legacy 扫描会漏（重构时应改为「以清单为准、文件名仅作兜底」）。

历史兼容：v1.1.0 之前的分卷名为 `<pkg>-<CPId>-<part>.tar*` 且直接放在备份根目录；迁移时把 `-obb.tar` 重写为 `-apk_obb.tar`（`p004class.Cthrow.mo486native`）。

## 4. SharedPreferences 全键表

### 4.1 文件 `"settings"`（备份/恢复行为，`r2ixzp.toolkit.pref.Cwhile`）

| key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `backup_home` | String | 见下 | 备份根目录绝对路径 |
| `backup_ext` | String | `.tar.zst` | 压缩格式（`.tar`/`.tar.gz`/`.tar.xz`/`.tar.zst`/`.tar.lz4`） |
| `compress_level` | String | `"3"` | 1–19，超范围在 shell 里夹取 |
| `backup_self` | boolean | true | 备份时把自身 APK 复制到备份目录 `!app!.apk` |
| `display_time` | boolean | true | 列表是否显示时间 |
| `custom_backup_home` | boolean | false | 是否使用自定义备份目录（true 时备份根目录可长按修改） |
| `backup_app_icon` | boolean | true | 是否备份应用图标 |
| `compatibility_mode` | boolean | false | 恢复 APK 时改用 stdin 管道安装（兼容光速虚拟机等） |
| `sd<N>` | String | `""` | 每块存储上选中的**相对**备份子路径（如 `/Backups/BackupToolkit`），N 为存储序号 |

默认备份根目录推导（`pref.Cwhile` 静态块）：

```
backup_home 为空 → <存储真实根> + (sd<N> 为空 ? "/Backups/BackupToolkit" : sd<N>)
存储真实根 = FileSystemService("/sdcard").getCanonicalPath()（失败退化为 "/sdcard"）
```

即默认 `<sdcard>/Backups/BackupToolkit`。

### 4.2 文件 = 包名（UI 状态，`p009else.Cimport.f1647extends`）

| key | 类型 | 说明 |
|---|---|---|
| `version` | String | 形如 `"1.1.1_1113"`，用于「首次/升级后弹更新日志」 |
| `show_app_description` | int | 0/1，首次启动的免责声明弹窗是否已确认 |
| `env_version` | int | 当前为 `20`；与代码常量不一致时重新解压 `assets/bin`（升级二进制时的迁移位） |
| `app_sort` | int | 排序模式索引（0=应用名 1=安装时间 2=更新时间 3=备份时间） |
| `reverse_order` | boolean | 倒序 |
| `display_system_app` | boolean | 是否列出系统应用 |
| `top_version_diff` | boolean | 「置顶不同版本」的备份条目 |
| `finish_cancel` | boolean | 「完成后取消选项」（批量任务中出错后是否清空勾选） |
| `file_backup_list` | String | 默认 `"DCIM:Download:Pictures"`，冒号分隔的目录名列表（文件备份 UI 用，功能未实装，见 `05`） |

## 5. 日志

| 项 | 位置 | 实现 |
|---|---|---|
| 错误日志 | `/sdcard/Android/data/<pkg>/files/log/error.log`（+ `.old`） | `p003catch.Cwhile`：`System.err/out.close()` 后自建 `PrintStream`；每次写前打印一行版本/状态头 `version:1.1.1(1113) \| <flag> \| SDK`，并通过 Messenger 让 UI 弹「捕捉到错误！请看日志！！」 |
| 日志轮转 | 同上 | 超过 1 MB 时**本应**重命名为 `.old`，但代码写成 `f660default.compareTo(file2)`（见 `07` 缺陷），实际不会轮转 |
| 查看/清理 | `LogsActivity` | 读取 `.old` + `error.log` 拼接展示；「清理日志」= 关闭流 + root shell `rm -rf '<log dir>'` |
| 崩溃 | `CrashActivity`（`:crash` 进程） | 展示崩溃堆栈 + 提供「重启应用」；该进程跳过整个 Application 初始化 |

> 之所以把日志放到 `/sdcard/Android/data/<pkg>/files/`，是因为 **root 侧 shell 和 UI 进程都要能访问**（`p005const.Cthrow` 覆写了 `getExternalFilesDir()` 直接拼这个路径，root 进程里没有可用 Context）。

## 6. 引擎与元数据的一致性约束（重构必须处理）

| 现状 | 风险 |
|---|---|
| 分卷文件与 JSON 是**两套真值**：JSON 说有几条备份，磁盘上才真有分卷 | JSON 写失败 → 分卷存在但列表里看不到；分卷被外部删除 → 列表点进去「未找到备份」 |
| 扫描时用 `filename.startsWith("<backupTime>-")` 判断某档位是否存在 | 只有文件名，无法知道分卷是否完整/损坏 |
| 无清单校验字段（无 size / sha256 / 分卷数量） | 无法做完整性校验与断点续传 |
| `backupTime` 既是主键又是文件名前缀 | 迁移/合并时依赖时间去重（`updateBackupDirStructure` 按 `backupTime` 去重合并） |
